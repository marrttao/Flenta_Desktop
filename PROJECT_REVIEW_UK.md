# Огляд та виправлення Flenta Desktop

Дата: 1 листопада 2026 року.

## Що переглянуто

Структуру React/Vite-проєкту, npm-скрипти, ESLint і TypeScript-конфігурацію, сховище та його адаптери, хуки валют, API-клієнти, керування авторизацією, темою, локалізацією, сповіщеннями та базовими модальними вікнами, наявні банківські тести. Це вибірковий огляд коду, а не повний аудит усіх сценаріїв застосунку.

Зміни обмежено конкретними дефектами. Публічні інтерфейси, назви ключів збережених даних, залежності, дизайн і протокол взаємодії з бекендом збережено. Мінімізацію коду для production уже виконує Vite під час збірки; 

## Виправлення

### 1. Завершення запитів валютних курсів

Файл: `src/features/currency/hooks/useCurrencyRates.ts`.

Хук створював `AbortController` та прапорець `active`, але не повертав функцію очищення ефекту. Старий запит міг оновити стан після зміни базової валюти та перезаписати актуальні результати; при демонтажі запит продовжував виконуватися.

Додано очищення: `active = false` і `controller.abort()`. Обробники старого запиту більше не змінюють дані, помилку чи стан завантаження. Це також коректно обробляє повторний запуск ефектів у React StrictMode.

### 2. Чисті оновлення списку валют

Файл: `src/features/currency/hooks/useUserCurrencies.ts`.

Функції додавання, видалення та перестановки валют викликали допоміжну функцію всередині функціонального оновлення `setCurrencies`. Вона записувала дані у сховище і повторно викликала `setCurrencies`.

Прибрано вкладені оновлення стану. Запис у сховище перенесено до `useEffect`, залежного від актуального списку. Функції оновлення тепер лише розраховують наступний стан; повторний виклик таких функцій у StrictMode не створює побічних ефектів. Початковий список також записується після монтування. Формат даних і алгоритми додавання, видалення та перестановки збережено.

### 3. Захист збережених даних від несеріалізованих значень

Файл: `src/storage/services/storageService.ts`.

Для `undefined`, функцій і символів `JSON.stringify` повертає `undefined`, а не JSON-рядок. Раніше це значення передавалося адаптеру: localStorage міг зберегти рядок `"undefined"`, який не можна прочитати через `JSON.parse`.

Додано перевірку результату серіалізації. Такі значення тепер ігноруються, а попереднє значення ключа зберігається. Звичайні JSON-значення, включно з `null`, працюють як раніше.

### 4. Запуск тестів у Windows

Файл: `package.json`.

У поточному Windows/Node 20 середовищі команда `node --test tests/*.test.mjs` завершувалася помилкою: шаблон передавався як буквальне ім’я файлу. Замінено на `node --test tests`, щоб Node сам знаходив тести в каталозі.

### 5. Регресійні тести сховища

Файл: `tests/storage.test.mjs`.

Додано перевірки серіалізації та читання JSON, збереження попередніх даних при передаванні несеріалізованих значень, обробки пошкодженого JSON без винятку та очищення лише ключів застосунку зі збереженням сторонніх даних. Для завантаження TypeScript використано вже наявний Vite; нових залежностей немає.
