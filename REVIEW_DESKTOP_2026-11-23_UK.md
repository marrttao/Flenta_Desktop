## Знайдені та виправлені дефекти

### Ключі повторних адмінських команд

Файл: `src/features/admin/api/adminOperations.ts`.

Помічник зберігав лише одну незавершену команду. Послідовність A → втрачена відповідь → B → втрачена відповідь → A отримувала новий ключ замість ключа першої A. Для зміни балансу це створювало ризик повторного виконання вже прийнятої сервером команди.

Тепер окремі незавершені команди зберігаються в Map за їхнім fingerprint. Повернення до A використовує початковий ключ. Паралельні виклики однакової команди ділять один запит. Після успішної відповіді ключ звільняється.

Пароль підтвердження, як і раніше, не входить до business fingerprint: виправлення пароля не створює нову фінансову команду. Маршрути, payload і серверна авторизація не змінювалися. Ключі залишаються в пам’яті конкретного помічника; відновлення після закриття діалогу чи перезапуску браузера не додавалося.

До `tests/admin-operations.test.mjs` додано два сценарії. На початковому коді вони падали: ключ A змінювався на key-3, а паралельні виклики робили два запити. Після виправлення обидва проходять.

### Запуск тестів у Windows

`npm test` з початковим `node --test tests/*.test.mjs` не працював у наявному Node 20 на Windows: шаблон сприймався як буквальне ім’я файлу.

Додано `scripts/run-tests.mjs`, який явно знаходить `.test.mjs` лише в кореневому каталозі tests і передає список Node без shell-шаблонів. Це також не запускає тести вкладених репозиторіїв. Скрипт не додає залежностей і передає exit code тестового процесу.
